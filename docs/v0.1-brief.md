# v0.1 実装の指示書

この文書は、Claude Code（クラウド）に v0.1 の実装を依頼するための指示書です。
仕様の本体はリポジトリ直下の「時間予算管理アプリ_仕様書_v1.2.md」です。**必ず先に全文を読んでください。**

## 背景

- このアプリは「不規則な生活でも、自分が大切にしたい活動の時間を確保する」ための、iPhone向けPWAです。
- 1日24時間を先に配分し、起床を1日の起点にして、計測を積み上げて実績を正直に見せる思想です。
- 仕様書の各項目には出どころが付いています：【要望】ユーザー本人／【合意】提案に同意／【決定】レビューで決定／【保留】実装後に見直し。
- ユーザーは「催促される」「カウントダウンで追われる」表示を明確に嫌っています。残り時間の表示は意図的に外してあります。
- 同じ仕様書で別のAI（Codex）も並行開発し、実際のiPhoneで操作感・計測の正確さ・データ保存を比べます。見た目より、計測ロジックとデータの正しさを優先してください。
- 通知は iOS の PWA ではローカル通知が使えないため、v0.1 では実装しません（v0.2 で Web Push サーバー）。
- 子アクション・ポモドーロ・繰り越し・固定予定は v0.1 の範囲外です。
- ユーザーはプログラマーではありません。報告は専門用語を避け、日本語で平易に書いてください。

## 作るもの

仕様書 §16「v0.1：毎日使い始められる最小の形」の9項目すべて。受け入れ条件は §17（v0.1 の16項目）。

## 守ること

- 仕様書で【要望】と書かれた項目はユーザー本人の要望なので、変更しない。【決定】を変える必要が出たら、理由を README の「仕様からの変更」節に書く。
- §1「しないこと」を厳守：催促・提案・警告・就寝までのカウントダウンを出さない。超過や未達は中立な事実として表示する。
- 日本語UI、スマホ縦画面・片手操作が前提。確認ダイアログの代わりに「取り消し」トースト。
- v0.1 はサーバー不要。静的ホスティングで動くこと。ログインなし、IndexedDB に保存、オフライン動作。
- 時刻は UTC で保存し、表示時に端末のタイムゾーンへ変換。計測中の記録は終了時刻 null で、累積は表示時に現在時刻との差で計算（§6.8、§14.2）。
- 計測記録はサイクルに紐づけない。サイクルの所属は起床イベントの並びから計算で求める（§14.2）。

## 技術構成（推奨。合理的な理由があれば変えてよい）

- Vite + React + TypeScript
- IndexedDB は Dexie（または idb）
- vite-plugin-pwa（manifest、Service Worker、更新通知「新しいバージョンがあります」）
- Vitest でロジックのテスト
- GitHub Pages で公開：GitHub Actions のワークフロー（main への push で `dist` をデプロイ）。Vite の `base` は `/time-budget-app/`。
- 外部のUIライブラリは最小限。グラフ（タイムラインバー、進捗バー、ドーナツ）は SVG で自作してよい。

## 進め方

1. まずドメインロジックをテスト付きで作る：§3 の用語（サイクル、カテゴリー別合計、計測時間（重複除外）、未計測時間）、起床イベントからのサイクル導出、サイクル境界をまたぐ記録の分割、睡眠が前サイクルに全量入ること、起床時刻修正後の再計算、同時計測の重複除外。ここに自動テストを必ず書く。
2. 次にデータ層（Dexie のスキーマ、スキーマバージョン、JSON エクスポート・インポート、`navigator.storage.persist()`）。
3. その後 UI：今日タブ（タイムラインバー、カード、睡眠中画面）、配分タブ（ドーナツ、予算編集、テンプレート1つ）、記録タブ（サイクル一覧・詳細・記録修正・エクスポート）、設定（止め忘れ閾値、カテゴリー管理）。
4. 止め忘れ検知（§6.5）、就寝の後入力（§5.5）、取り消しトースト（§6.7）、カードの長押し同時計測と自動停止（§6.2）を忘れない。カードのタップはスクロール中に発火しないようにする（§7.3）。
5. 小さなコミットに分け、ブランチを切って PR を main に対して開く。PR 本文に「実装済み／未実装」の一覧と、§17 の各項目をどう確認したかを書く。

## README に必ず書くこと

- ローカルでの起動方法（npm install / npm run dev）
- 公開方法（GitHub Pages の有効化手順：Settings → Pages → Source を GitHub Actions にする）
- iPhone での使い方（Safari で開く → 共有 → ホーム画面に追加。最初からホーム画面のアイコンから使うこと）
- 実装済み機能と未実装機能の一覧

## 完了の条件

- `npm run build` と `npm test` が通る。
- §17 の16項目が、ブラウザのモバイル表示で手動確認できる状態。
- PR が開いていて、本文に上記の一覧がある。
- 仕様書ファイルは変更しない（質問や提案は PR 本文か README の「仕様への質問」節に書く）。
